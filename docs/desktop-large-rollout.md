# 桌面语音投递：大历史记录修复

后续已切换为直接订阅桌面状态通知，Windows 生产语音链路不再使用本文的历史读取方式。当前实现见 [桌面任务状态通知](desktop-state-notifications.md)。以下保留为问题诊断和修复过程记录。

2026-10-05，S1 绑定当前聊天后，两次语音请求在投递前失败，错误为 `output_too_large`。桌面投递账本中没有这两个请求的记录。当前聊天历史文件约 8.9 MB，其中一条 `event_msg/item_completed` 记录为 2,217,796 字节，超过原读取器的 1 MiB 单行上限。

初步修复曾将单行上限提高到 16 MiB。最终改为复用有界 JSON 流式解析器的生命周期模式，取消整行缓冲和累计文件大小导致的拒绝；工具输出、图片和 content 数据只验证语法，不捕获、不复制到 VoxQueue 的投递记录。只保留记录类型、会话和 turn 标识、最终回答的有界片段及错误是否存在，用于判断空闲和匹配完成。每次最多扫描 4 MiB，未读完历史或存在未写完记录时不会判为空闲，后续轮询继续。

仍保留文件身份、截断、JSON 语法、嵌套深度和匹配 turn 完成状态检查。历史任务完成不会代替新任务完成，错误详情不会被当作成功回答。界面投递说明去掉固定的“运行期间请等待”，避免失败时暗示任务仍在运行。Codex 自己保存的历史文件保持原样。

验证：桌面协议测试 8 项、Windows 存储测试 6 项、目录路径测试 1 项通过。含 3 MiB 工具事件、20 MiB 单条输出跨轮询与半条写入、图片及工具输出投影丢弃、嵌套伪生命周期忽略、字段顺序及重复错误字段、非空回答仍带错误时判失败、无关字段非法 JSON 拒绝。另用当前真实聊天历史从开始到末尾运行只读重放测试并通过，没有发送新提示。

本次修复没有重发旧失败语音。新的真实 S1 语音投递仍需用户实际操作确认；历史失败状态保留至新的任务更新槽位状态。

Windows release 和 NSIS 构建成功，流式版本已更新到本机。两个安装程序文件的哈希与最终构建一致，Host 健康检查为 ready。更新前无进行中的语音任务、总结领取或播放租约；保留旧二进制备份、数据库和 S1 当前聊天绑定。安装包 SHA256：`641B674181650113067388D384029FAC1F69BBBA5E4714471941244A2B157320`。
