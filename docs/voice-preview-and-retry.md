# 播报试听与失败重试

2026-10-06，按第 1、4 项增加两个功能。

## 播报试听

在工作台的“播报设置”中选择音色、语速后点击“试听播报”，无需先保存。使用同一 MiniMax 模型生成固定示例，仅点击时调用服务。试听不发送到 Codex，也不写入回答的待听队列。

试听音频短暂经过私有运行目录，Host 只接受 UUID 对应的固定文件名，检查文件类型、大小、EIAD 格式后读取并删除。每次生成使用独立标识；并行生成和播放排队会被拒绝。等待键盘最多 30 秒。

新固件用 EIHB 音量扩展版本 2 声明支持试听。Host 使用通过认证的 EIMB v5（36 字节）携带一次性试听标识，保持普通状态报文 v4。键盘先验证 HMAC 和当前心跳序列，再发起带该标识的 EIPR 请求。音频传输仍使用已有认证、加密和完成确认协议。

固件中的试听独立于四个槽位的总结状态；播放完成不消费总结，不改变待听队列。忙于录音或播放时等到空闲；开始录音可以打断试听。旧固件仍能使用语音任务和音量显示；试听会明确提示更新固件，不会先产生合成费用。

## 失败重试

失败槽位显示保留的识别文字和“重试发送”。后台验证原请求、槽位、目标对话和绑定代次一致，再追加持久任务。一个失败请求只能产生一个确定性子请求，连续点击和传输重放不会重复入队。新的子请求再次失败时可以继续重试。

改绑后旧请求不能投递到新对话。原文字和工作目录保留，使用现有调度器执行，没有读取 Codex 工具输出。可能已投递但结果未确认的任务，界面提示重新发送可能产生重复请求，点击即为一次显式重新发送。

## 验证与交付

- Rust 重试集成测试：原文字、工作目录、目标绑定保留；连续点击幂等；改绑及未绑定槽位拒绝。
- 真实 UDP 试听测试：新版能力心跳、认证触发、篡改请求拒绝、加密音频传输、完成 ACK、没有总结事件；已有试听占用时拒绝第二次提交。
- C++ 协议测试：v3/v4 兼容、v5 标识读取、篡改、截断和空指针拒绝；音量扩展编码测试。
- ESP-IDF 应用固件和 Windows 桌面安装包已构建；恢复包仍为三段写入，保留配网、音量、声音资源。

硬件试听仍需将新版固件写入实物键盘后验收；模拟 UDP 不能证明实物扬声器已经播出。当前固件没有远程进入 ROM 下载模式的接口，烧录需要实体开关或 BOOT 操作。

新应用镜像：`firmware/releases/version-reporting-r3-20261006.bin`，SHA-256 `61f08d4caf8d00eda9862a250f99abc2a4f2b58be8b6a6917a9f0c3a71bc633a`。

本机软件与 Host 已自动更新，两个程序与三份资源逐项校验一致；Host health 返回 ready。只读状态确认当前实物仍上报旧版能力，`preview_supported=false`，仅有正常 HID 设备，尚不能执行新固件试听。未自动重发用户历史失败任务，未调用电脑 UI 自动化。

启动就绪修正：桌面试听命令最多等待 8 秒接收有效能力心跳；只有键盘在线且持续报告不支持时才提示固件版本，未收到心跳时提示等待联网。本机后来已确认 `preview_supported=true`，实物新版固件已生效，用户正在验证实际播出。

试听实板修正：用户已成功写入支持试听的固件，但空闲时没有声音。固件接收音频帧时仍检查总结槽位，试听没有总结记录，因此被拒绝。现将该检查仅用于普通总结播放；认证、身份、顺序与音频边界检查保持。Host 上报 waiting/streaming/completed/failed，界面按真实完成确认显示结果，准备成功不代表扬声器已播放。实板修正版仍待用户烧录并验收。

槽位清除扩展：点击每个槽位的“清除待听”，同一事务将已有失败输入标记为已清除，同时清除待听总结。数据库 schema 8 增加持久清除标记，保留历史记录；清除后不显示识别文字、失败状态和重试按钮，并拒绝旧请求的重试。校验当前绑定代次，不取消排队或运行任务，也不隐藏此后发生的新失败。已覆盖旧数据库升级、重启持久化、槽位隔离、过期绑定拒绝、运行任务保留及新失败重新显示。
