# Codex 桌面任务状态通知

Windows 语音投递的空闲判断、任务完成判断和总结收集均改为订阅 Codex 桌面 IPC 状态通知，不再读取 rollout 聊天历史文件。macOS 原有后端保持原实现。

本机 Codex 26.930.4958.0 的协议为 `thread-stream-following-changed` 版本 1 和 `thread-stream-state-changed` 版本 11。订阅后收到状态快照，之后收到带修订号的增量补丁。VoxQueue 只保留任务标识、状态、错误是否存在、输入和最终回答；工具和图片位置使用空占位，正文不保存。桌面通知本身的初始快照可能包含工具数据，VoxQueue 收到后立即丢弃这些字段。

状态必须来自目标聊天的拥有者且修订号连续。缺失补丁会请求新快照，重连也重新订阅。失败、中断、有错误的部分回答、尚未收到最终回答均不会判为成功。发送回执仅表示任务被接受；持久投递账本继续防止不确定发送被自动重发。

总结仅提取最终回答及有界输入文本，工具列表为空。数据库加入通知任务基线和已见 turn 状态，迁移到版本 7；首次订阅已有历史不会把旧回答重新变成待听项，后续完成和断线期间结束的已见任务可恢复，重复通知和清除后的快照不恢复旧待听项。

## 验证

定向 Rust 测试 18 项通过，覆盖通知来源和目标匹配、修订缺口、完成与最终回答匹配、失败及中断、旧历史基线、重连去重、延迟最终回答、清除后不重建和新完成内容继续生成。另进行了两次真实桌面 IPC 验证：

- 通知订阅和最终回答匹配：turn `01a10c8a-10af-7ba1-ac76-b15978429b1c` 完成。
- 实际投递运行器与独立总结观察器：turn `01a10c8c-3d8f-7240-b79a-5cdf823d6abc` 完成，投递账本为 completed，总结库恰好写入一条，仅包含输入和回答。验证使用临时数据库，未更改用户槽位绑定。

这些真实验证均没有读取聊天历史内容。该 IPC 接口属于当前桌面安装版本的内部协议；版本不匹配时拒绝判定完成，不退回扫描历史文件。
