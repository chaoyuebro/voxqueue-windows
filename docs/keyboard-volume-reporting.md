# 键盘扬声器音量上报

2026-10-06：在“工作台 → 播报设置”页单独显示键盘扬声器音量，区别于回答音频音量滑块。

键盘启动时从 NVS 读取音量，转动旋钮后更新本地扬声器，并通过认证心跳立即报告当前级别。EIHB 保留 80 字节总长和现有 EISD HMAC：字节 6 为 0–10 的音量级别，字节 7 为扩展版本 1；旧固件为两个零字节，继续兼容，但界面显示等待上报。

Host 只接受认证通过且版本、级别有效的报告，转换为 0–100% 显示。超过 12 秒未收到有效报告即隐藏旧读数；桌面每 3 秒读取状态，Host 离线时显示离线。旋钮每档为 10%，持续调整会触发新心跳，不等周期定时器。

验证：真实 UDP 测试验证 0%、30%、100% 更新、篡改包拒绝、级别及版本范围拒绝、12 秒超时清除以及旧固件兼容。C++ 心跳编码测试验证 0–10 全部级别和旧报文默认值。桌面 JavaScript 语法检查通过。

新版应用镜像：`firmware/releases/keyboard-volume-20261006.bin`，SHA-256 `93d93d9e9177841ba7a91c4a52517587370cf5a272dc2ce274076b203fe85ed7`。沿用已验证的引导程序与分区表，不更改配网、声音资源布局。

Windows 工具链的 objdump/linker 对中文路径不兼容。此次仅在生成的构建文件中使用映射盘 V: 作为 ASCII 路径，应用 ELF 链接成功后按 ESP-IDF 的相同 esptool elf2image 参数生成镜像；不重建发布引导程序。V: 临时映射在生成结束后移除。未修改 SDK 源码。

桌面程序与 Host 已构建并更新到本机，三份内置镜像与两份程序逐一校验一致；重新启动后 Host health 返回 ready。仍需用户通过“固件烧录”刷入实板，并验证旋钮操作对应界面读数；不能以 UDP 仿真代替实板验收。

串口恢复修正：Windows 将 ESP32-S3 的 COM7 枚举为 VID_303A&PID_1001&MI_00 子接口，旧版只读取复合父设备的 PortName，导致实际串口存在时仍等待超时。现同时读取直接串口与 MI_00 接口，通过 Config Manager 验证接口在场、已启动，并沿父节点获取原设备序列号；仍拒绝无关、断开的串口及多设备。此次已观察到实物 COM7 与父设备 28:84:85:91:D9:68，随后设备回到正常 HID 模式。
